# 加密相簿（0.1.5）

在「相簿 → 加密相簿」建立相簿。輸入名稱及至少 12 個字元的密碼，建立後以密碼解鎖。名稱本身也經過加密，因此鎖定清單以相簿識別碼區分。

## 使用方式

- 「選擇手機照片／影片」開啟系統選檔器時先鎖定；返回後重新解鎖，再按「加密上傳」。
- 「從雲端照片／影片加入」可選擇已有的雲端照片或影片，直接在記憶體中讀取、加密並上傳副本。
- 匯入會保留手機或雲端的來源原檔，不會把原有普通相簿自動轉換成加密相簿，也不會自動刪除來源原檔、普通相簿的離線副本或既有備份。
- 鎖定頁固定顯示「指紋解鎖」入口。首次使用時，先輸入相簿密碼解鎖，再按頁面上方「下次使用指紋解鎖」區塊中的「啟用指紋解鎖」，完成系統辨識驗證後，下次就能直接點選指紋入口。尚未登錄指紋、缺少強式生物辨識或硬體暫時不可用時，畫面會顯示原因；從系統設定返回時會重新檢查。系統也可能提供裝置支援的強式臉部辨識；沒有可用生物辨識時仍可使用相簿密碼。每次解鎖都需重新驗證。
- 按「鎖定」、返回相簿清單、退出加密頁面、Activity 進入背景或遭銷毀，均清除目前工作階段。切到背景再返回，必須重新解鎖。
- 加密頁面設定 `FLAG_SECURE`，要求系統阻止截圖、錄屏及最近使用畫面預覽。登出刪除本機的指紋金鑰與包裹資料；雲端密文保留。

目前支援裝置能解碼的靜態圖片，單張原檔上限 32 MiB；原始檔案位元組及 EXIF 都保存在密文內。預覽最長邊不超過 2048 像素，縮圖最長邊不超過 320 像素。此版不提供明文匯出、分享、編輯、改密碼、普通資料夾原地加密及背景加密傳輸。

上傳在加密頁面前景執行。只有伺服器確認成功才顯示完成；離開會取消網路請求，已完成的項目保留。若伺服器已寫入但回覆遺失，重新整理後先確認照片是否存在，再決定是否重試；不會覆蓋既有密文。中斷可能留下孤立的加密縮圖、影片區塊或未完成的相簿資料夾；此版不自動清理孤立區塊，也不跨程序續傳加密影片。

## 加密影片

0.1.4 新增手機及雲端影片匯入，單部上限 32 GiB。照片仍維持 32 MiB 上限。影片每次讀取最多 1 MiB，獨立加密並上傳每一塊，最後才發布加密索引；上傳進度顯示已完成區塊的大小，原始來源仍保留。伺服器未確認所有區塊與索引成功前，不標記完成。

點選相簿中的播放圖示，可播放／暫停、拖曳進度及調整系統音量。影片以播放圖示呈現，此版尚不產生影片封面。播放器直接從伺服器取得需要的加密區塊，驗證完整性後交給 Media3；不先下載整段明文影片，也不使用磁碟播放快取。自訂資料來源只保留一個 1 MiB 解密區塊，播放器另有受限的記憶體載入緩衝。播放與拖曳需網路連線；格式／編碼由裝置與 Media3 決定，不支援時顯示提示及重試按鈕，不會轉交外部 App。

返回相簿、鎖定或進入背景會停止播放器及取消讀取，清除區塊緩衝；再次播放從頭開始。播放器及系統解碼器內部記憶體仍適用下方「清除範圍」的限制，不宣稱可逐位元抹除作業系統的所有副本。資料來源的 seek／EOF 行為依 [Media3 DataSource 規格](https://developer.android.com/reference/androidx/media3/datasource/DataSource) 實作。

## 儲存與密碼

雲端專用資料夾為帳號根目錄下的 `Nextcloud Photo Vault`。其中每個相簿使用隨機 UUID 資料夾，每張照片也使用隨機 UUID 檔名。照片及影片內容、原檔名、相簿名稱和縮圖皆以 AES-256-GCM 加密並驗證完整性。伺服器仍能看見密文大小、檔案數量、修改時間及存取紀錄。

每本相簿有隨機 256 位元主金鑰。密碼以隨機 16-byte salt、PBKDF2-HMAC-SHA256、600,000 次迭代產生包裹金鑰；密碼本身不儲存。此工作因子參考 [OWASP 密碼儲存指引](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。請使用長且不重複的密碼；取得雲端密文的人仍可離線猜測弱密碼。

指紋功能使用 Android Keystore 中要求每次強式生物辨識授權的 AES 金鑰，再包裹相簿主金鑰。解包必須使用成功驗證後的 `CryptoObject`，不是以「驗證成功」布林值繞過解密。金鑰設定為生物辨識登錄變更後失效，做法參考 [Android 生物辨識與加密文件](https://developer.android.com/identity/sign-in/biometric-auth)。換手機、解除安裝、刪除裝置鎖定或生物辨識失效後，請使用相簿密碼。

請備份完整的專用資料夾，尤其是每本相簿的 `vault.json`，並妥善保存密碼。密碼及可用的指紋解鎖都遺失時，開發者與 Nextcloud 管理員無法復原。不要在網頁端改名 UUID 資料夾或密文檔名；它們參與完整性驗證。這是本 App 的獨立格式，並非 Nextcloud 官方端對端加密格式，Photos 網頁及其他相簿 App 無法直接閱讀。

## 清除範圍

加密相簿不使用 Coil、一般縮圖磁碟快取、Room 媒體索引、MediaStore 或明文暫存檔。瀏覽只保有當前工作階段需要的記憶體圖片及影片緩衝，離屏縮圖即釋放。鎖定時同步清零工作階段主金鑰、回收其 Bitmap、移除照片與相簿名稱的畫面狀態，取消專用網路請求、停止並釋放播放器、清除影片區塊緩衝；處理中的位元組緩衝區在清理區塊清零。程序終止後沒有明文檔案需要恢復清理。

「立即清除」指立即撤銷 App 存取解密內容並釋放其持有的快取；Android/JVM 字串、圖形驅動及作業系統可能保有內部記憶體副本，因此不宣稱能證明所有實體 RAM 位元均已清零。相簿主金鑰的生物辨識加密包裹資料會保留，供下次授權解鎖，並不含明文密碼或照片。

## 格式 v1

所有整數及 JSON 文字依下列規格解碼。GCM envelope 為 `12-byte random nonce || ciphertext || 16-byte authentication tag`。AAD 為 UTF-8 的 `NextcloudPhoto/vault/v1/` 加上指定內容。

| 檔案／欄位 | 內容與 AAD |
| --- | --- |
| `vault.json` | `version: 1`、`id`、`iterations: 600000`、Base64 `salt`、`wrappedKey`、`title` |
| `wrappedKey` | PBKDF2 產生的金鑰加密 32-byte 相簿主金鑰，AAD：`albumUUID/key` |
| `title` | 相簿主金鑰加密 UTF-8 相簿名稱，AAD：`albumUUID/title` |
| `photoUUID.nct` | 相簿主金鑰加密 JPEG 縮圖，AAD：`albumUUID/photoUUID/thumbnail` |
| `photoUUID.ncp` | 相簿主金鑰加密 `4-byte big-endian 檔名字節長度 || UTF-8 檔名 || 原始檔案位元組`，AAD：`albumUUID/photoUUID/photo` |

影片擴充格式沿用相簿主金鑰與 GCM envelope，舊 `.ncp` 照片保持相容：

| 檔案 | 內容與 AAD |
| --- | --- |
| `videoUUID-index.nvc` | 1 MiB 以內的原始影片區塊；index 從 0 起算，AAD：`albumUUID/videoUUID/video/index` |
| `videoUUID.ncv` | 加密 UTF-8 JSON：`version:1`、`id`、`name`、`mime`、`size`、`chunkSize:1048576`、`chunks`；AAD：`albumUUID/videoUUID/video-manifest` |

索引中的 `chunks` 必須等於 `ceil(size / chunkSize)`，size 為 1 至 32 GiB；每一塊解密後的長度也必須與索引吻合。區塊不可交換、裁短或跨影片使用。影片必須保留全部 `.nvc` 與 `.ncv`；舊版 App 會忽略影片，仍能閱讀舊照片。檔案副檔名會揭露它屬於照片或影片。

照片先上傳加密縮圖，最後寫入 `.ncp`；影片最後寫入 `.ncv`。只有 `.ncp` 與 `.ncv` 列入相簿。所有寫入帶 `If-None-Match: *`，拒絕覆蓋同名物件。普通上傳／備份及 App 的普通移動入口不允許把明文寫進專用資料夾；外部 WebDAV 用戶端仍能操作該目錄，請勿從外部直接放入未加密照片。

目前已完成自動化及模擬伺服器測試，尚未經獨立密碼學審查；真實 Android 16 指紋、鎖屏、最近使用預覽及 Nextcloud 34.0.3 讀寫仍待實機驗收。
